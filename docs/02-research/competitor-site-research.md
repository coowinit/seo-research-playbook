# 竞争网站研究：从单页分析升级到网站级判断

本模块用于研究一个竞争网站为什么能够持续覆盖某类搜索需求，以及它在网站结构、产品体系、内容体系、内部链接、技术基础和外部引用方面建立了什么优势。

竞争网站研究的目标不是“复制对方网站”，而是回答：

```text
它主要服务谁？
↓
网站如何组织产品与内容？
↓
哪些页面承担流量入口？
↓
产品页、指南页、工具页和资料页怎样互相连接？
↓
哪些主题已经形成明显优势？
↓
哪些部分只是品牌资源优势，无法直接复制？
↓
我们真正可以学习和改进什么？
```

---

## 1. 网站级研究与单页研究的区别

| 层级 | 主要问题 | 主要产物 |
|---|---|---|
| 单页竞争研究 | 某一个关键词下，哪些页面满足用户需求？ | 搜索结果研究、证据矩阵、内容缺口 |
| 网站级竞争研究 | 一个竞争网站如何系统承接多个主题和用户阶段？ | 网站结构图、页面类型矩阵、内容体系、内部链接与竞争优势判断 |

单页研究回答“这一页为什么可能表现好”。

网站级研究回答：

> **这个网站为什么能够长期覆盖一整类搜索需求。**

二者必须结合，不能互相替代。

---

## 2. 先确定研究对象，不要只选“大品牌”

建议同时选择 3—6 个不同类型的网站作为长期观察对象，例如：

- 直接产品竞争者
- 行业头部品牌
- 区域强势品牌
- 经销商 / 零售商
- 专业媒体 / 行业资料站
- 搜索结果中频繁出现但业务模式不同的网站

选择标准不是“品牌越大越好”，而是：

```text
与目标市场相关
+
与目标产品相关
+
搜索结果中真实出现
+
能提供可学习的网站结构或内容模式
```

如果只研究一个绝对头部品牌，容易把品牌知名度、广告投入、渠道优势误认为可以直接复制的 SEO 方法。

---

## 3. 所有竞争数据先分成三类证据

竞争研究很容易把“看到的事实”和“工具估计”混在一起，因此统一分为三类。

### A：直接观察事实

可以直接从公开网站确认，例如：

- 主导航有哪些栏目
- 产品类别有哪些
- 是否存在比较工具
- 是否有安装指南
- 是否有案例库
- URL 是什么
- 页面之间如何链接
- 是否存在多地区版本

记录方式：

```text
事实
+
来源 URL
+
检查日期
```

### B：第三方工具估算

例如通过 Ahrefs、Semrush、Similarweb 等获得：

- 估算自然搜索流量
- 估算关键词数量
- 估算流量国家分布
- 估算外链数量
- 估算引荐域名
- 第三方网站权威指标

必须写成：

> **估算 / 第三方指标**

而不是：

> “这个网站真实每月有 500,000 自然流量。”

不同工具的方法、数据库和更新时间不同，同一网站出现不同数字是正常现象。

### C：分析判断

例如：

- 这个网站可能把“项目规划工具”当成中上游获客入口。
- 该产品分类页可能是网站内部的重要枢纽。
- 该网站内容明显偏终端消费者，而不是 B2B 采购。

必须明确这是：

> **根据观察形成的判断，不是网站后台事实。**

---

## 4. 推荐研究顺序

不要一开始就导出几万个关键词。

推荐顺序：

```text
1. 企业与业务定位
↓
2. 主导航与网站结构
↓
3. 产品体系
↓
4. 页面类型
↓
5. URL 与目录体系
↓
6. 代表性页面与搜索入口
↓
7. 内容主题与用户阶段
↓
8. 内部链接与重要页面关系
↓
9. 技术 SEO 基础
↓
10. 外链与品牌引用
↓
11. 第三方流量 / 关键词估算
↓
12. 优势、缺口与可行动结论
```

这个顺序能避免出现：

```text
导出 50,000 个关键词
↓
得到一张很大的表
↓
仍然不知道竞争网站是怎么组织业务的
```

## 5. 工具组合与使用边界

竞争网站研究不要求一次购买所有工具。工具只是获取证据的方式，不能替代研究框架。

### 免费 / 基础组合

可以先使用：

- Google 搜索：发现竞争网站和代表性页面。
- `site:example.com 关键词`：抽样发现某类页面，但不能当作完整索引数量。
- 网站主导航和 Sitemap 页面：理解公开结构。
- `robots.txt` 与 XML Sitemap：辅助理解抓取与公开 URL。
- 浏览器开发者工具：查看页面结构、链接和网络请求。
- PageSpeed Insights / Lighthouse：观察性能问题线索。

Google 也明确说明，`site:` 搜索并不保证返回指定范围内的全部已索引网址，因此不要用：

```text
site:competitor.com
返回 8,000 条
```

直接下结论：

> “竞争网站只有 8,000 个收录页面。”

参考：
https://developers.google.com/search/docs/fundamentals/get-on-google

### 需要完整抓取时

可以使用：

- Screaming Frog
- Sitebulb
- 其他能够导出 URL、状态码、标题、Canonical、内部链接和点击深度的爬虫

重点用于回答：

- 网站到底有哪些公开可抓取页面？
- 页面类型如何分布？
- 哪些页面内部链接多？
- 哪些页面很深或孤立？
- 状态码、Canonical 和重复页面是否有系统性问题？

### 需要关键词 / 流量 / 外链估算时

可以使用：

- Ahrefs
- Semrush
- Similarweb
- 其他同类第三方数据库

但所有输出必须保留：

```text
工具名称
+
数据日期
+
目标国家 / 数据库
+
估算口径
```

不同工具之间不要强行要求数字完全一致。

### 技术栈识别

BuiltWith、Wappalyzer 等可以辅助判断：

- CMS
- CDN
- 分析工具
- 前端框架
- 部分第三方服务

但“用了什么技术”本身不是 SEO 优势。

例如：

```text
竞争网站使用 React
```

不能推出：

```text
React 有利于 SEO
```

只有当技术实现影响抓取、渲染、速度或维护效率时，这项观察才真正有价值。

## 6. 第一层：企业与业务定位

先回答：

- 它主要卖什么？
- 主要客户是谁？
- B2C、B2B 还是混合模式？
- 主要市场在哪里？
- 是否依赖经销商 / 承包商 / 零售商？
- 核心转化是什么？
- 是否存在样品、询价、报价、门店、经销商查找等不同转化？

SEO 必须放在商业模式中理解。

例如：

```text
品牌官网
→ 可能主要负责教育 + 品牌 + 线索分发

零售网站
→ 可能主要负责产品检索 + 价格 + 购买

B2B 制造商
→ 可能主要负责产品能力 + 技术资料 + 询盘
```

不能用同一标准评价。

---

## 7. 第二层：主导航与网站结构

记录主导航和重要二级入口，例如：

```text
Products
├── Decking
├── Cladding
├── Fencing
└── Railing

Resources
├── Installation
├── Technical Documents
├── Warranty
└── Case Studies
```

重点观察：

- 用户从首页到核心产品需要几层？
- 产品分类与子分类是否清晰？
- 指南是否独立成知识体系？
- 专业用户是否有独立入口？
- 资料中心是否能按产品过滤？
- 是否有项目规划、计算器、比较工具等功能页？

Google 当前公开指南也强调，搜索引擎会根据页面之间的链接关系理解网站结构和相对重要性；因此导航与内部链接是网站级研究的重要对象。

参考：
https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure

---

## 8. 第三层：产品体系

竞争产品研究不要只记录“它有哪些产品”，还要记录层级。

例如：

```text
产品大类
↓
产品系列
↓
型号 / Collection
↓
颜色 / 规格 / 属性
↓
技术资料
↓
安装 / 维护
```

建议表格：

| 产品大类 | 系列 | 页面类型 | 主要卖点 | 技术资料 | 转化入口 |
|---|---|---|---|---|---|

重点判断：

- 分类页是否承担核心非品牌关键词？
- 系列页与单品页职责是否清楚？
- 技术资料是否与产品页连接？
- 产品比较是否独立成工具或指南？
- 不同目标用户是否看到不同资料？

---

## 9. 第四层：页面类型矩阵

不要只按“博客 / 产品”两类理解网站。

一个成熟产品网站可能包含：

| 页面类型 | 主要职责 |
|---|---|
| 首页 | 品牌与核心业务入口 |
| 产品分类页 | 承接核心产品搜索需求 |
| 产品系列页 | 细分系列与选择 |
| 单产品页 | 规格、特点、转化 |
| 比较页 | 商业比较型需求 |
| 安装指南 | 安装与支持需求 |
| 技术资料页 | 专业 / B2B 决策 |
| 案例页 | 经验和项目证据 |
| 计算器 / 工具 | 规划与决策辅助 |
| FAQ / 支持页 | 售前售后问题 |
| 经销商 / 承包商页 | 本地与渠道转化 |
| 专业用户中心 | 建筑师、设计师、施工方资料 |

真正需要研究的是：

> **这些页面怎样共同承接用户从了解、比较到行动的全过程。**

---

## 10. 第五层：URL 与目录结构

记录代表性 URL，不需要一开始抓取全站。

例如：

```text
/products/
/products/decking/
/resources/
installation/
compare/
professionals/
```

研究：

- 是否存在稳定目录逻辑？
- 内容与产品是否分区？
- 同一内容是否存在多个路径？
- 国家 / 语言版本如何组织？
- 参数网址是否大量产生？

注意：Google 通常不会只依靠 URL 目录推断网站结构，真实的页面链接关系更加重要。因此 URL 结构只能作为辅助观察，不能替代内部链接分析。

---

## 11. 第六层：代表性流量入口

如果有第三方关键词工具，不要只看“Top Keywords”。

应该把入口页面按职责分类：

```text
核心产品入口
比较入口
问题型入口
安装 / 维护入口
品牌入口
工具入口
案例入口
本地 / 渠道入口
```

建议记录：

| 页面 | 页面类型 | 主要主题 | 估算关键词 / 流量 | 证据类型 | 研究价值 |
|---|---|---|---|---|---|

重点寻找：

> **竞争网站真正获得搜索曝光的页面类型是什么？**

有些网站流量主要来自博客，有些则可能来自产品分类、工具或本地页面。

---

## 12. 第七层：内容体系

按主题而不是按发布日期研究。

例如 Composite Decking 网站可能形成：

```text
材料认知
├── what is composite decking
├── composite vs wood
└── PVC vs composite

成本与规划
├── cost
├── calculator
└── deck planning

安装
├── installation
├── joist spacing
└── fasteners

维护
├── cleaning
├── stains
└── scratches
```

研究：

- 是否存在明显的主题中心？
- 内容是否支持产品页？
- 产品页是否反向链接相关指南？
- 是否存在“指南 → 工具 → 产品 → 转化”的路径？
- 内容是否只为了流量，还是进入真实业务决策？

---

## 13. 第八层：内部链接与页面重要性

内部链接研究至少观察：

- 主导航链接
- 分类页到子页面
- 产品页到技术资料
- 文章到产品
- 产品到安装 / 维护
- 面包屑
- 页脚
- 相关内容模块
- CTA 链接

重点不是计算一个统一“内部链接数量”，而是理解：

```text
哪些页面被反复链接？
↓
哪些页面是网站枢纽？
↓
哪些页面离首页很深？
↓
内容流量最后被引导到哪里？
```

Google 的公开文档指出，网站内指向页面的链接关系和到达页面需要经过的链接数量，可帮助搜索引擎理解页面相对重要性。

因此竞争网站的内部链接结构具有研究价值，但不要把它简化成“链接越多排名越高”。

---

## 14. 第九层：技术基础

这里不重复完整技术 SEO 审计，只做竞争研究需要的高层观察：

- HTTPS 与规范域名
- robots.txt
- XML Sitemap
- Canonical
- 主要目录是否可索引
- JavaScript 是否影响核心内容
- 结构化数据类型
- 移动端体验
- Core Web Vitals / PageSpeed 线索
- 多语言 / 多地区架构

技术研究的目标不是证明：

> “竞争网站技术分数高，所以排名高。”

而是判断：

> 它是否存在明显技术优势或明显技术负担。

---

## 15. 第十层：外链与品牌引用

外链研究应该从“数量”升级为“来源结构”。

重点观察：

- 哪些页面最容易获得引用？
- 引用来自媒体、协会、经销商、承包商、学校、政府还是普通目录？
- 外链主要指向首页，还是工具、研究、案例、指南？
- 是否存在明显的合作伙伴生态？
- 是否有独特资源自然成为引用对象？

第三方工具可以辅助估算：

- 引荐域名
- 外链数量
- 锚文本
- 最常被链接页面
- 新增 / 丢失链接

但要明确：

```text
DR
DA
Authority Score
```

等都是第三方工具自己的评价指标，不是 Google 官方排名分数。

Google 也明确将为了操纵排名而创建或购买链接的行为列为链接垃圾风险，因此竞争研究不应演变成“照着竞争对手买链接”。

参考：
https://developers.google.com/search/docs/essentials/spam-policies

---

## 16. Search Console 数据与竞争网站数据不要混淆

自己的站点可以使用 Google Search Console 查看：

- 查询词
- 展示
- 点击
- 页面
- 国家
- 设备
- 外部链接样本
- 内部链接样本

需要注意，Search Console 的“链接”报告本身也不是网站全部链接的完整数据库，而是 Google 提供的链接样本和汇总视图。因此即使研究自己的网站，也不要把报告表格行数直接理解为全网所有链接数量。

参考：
https://support.google.com/webmasters/answer/9049606

竞争网站没有对方授权时，无法获得其真实 Search Console 后台数据。

因此竞争网站的：

```text
流量
关键词
外链
```

通常来自第三方估算。

不要在报告中写：

> “竞争对手 Search Console 显示……”

除非你确实拥有授权数据。

---

## 17. 不建议用一个“竞争网站总分”代替判断

可以为研究方便制作评分，但不建议最终只留下：

```text
Trex 92 分
Competitor B 81 分
我们 68 分
```

更有价值的是拆成不同维度：

| 维度 | 观察 |
|---|---|
| 产品体系 | 强 / 中 / 弱 |
| 网站结构 | 强 / 中 / 弱 |
| 内容覆盖 | 强 / 中 / 弱 |
| 技术资料 | 强 / 中 / 弱 |
| 内部链接 | 强 / 中 / 弱 |
| 原创工具 | 强 / 中 / 弱 |
| 外部引用 | 强 / 中 / 弱 |
| B2B 支持 | 强 / 中 / 弱 |

然后说明证据和判断理由。

---

## 18. 最终必须输出“可行动结论”

竞争研究完成后，不要停在：

> 对方网站做得很好。

至少输出四类结论。

### 保留我们的优势

哪些地方不需要跟随竞争对手？

### 应补齐的基础能力

例如：

- 缺少产品分类页
- 缺少安装资料
- 缺少技术文档中心
- 内容和产品没有内部链接

### 可形成差异化的机会

例如：

- 原创测试数据
- B2B 技术资料
- 项目案例
- 更清楚的产品比较
- 面向不同气候 / 地区的应用指南

### 暂时不做

例如：

- 竞争网站有复杂 3D 设计器，但当前业务规模不需要。
- 大量本地承包商目录依赖其渠道体系，我们没有条件复制。

这能避免“看到什么就做什么”。

## 19. 推荐的最小研究产物

一个竞争网站至少保留：

```text
基础信息
主导航结构
产品体系
页面类型矩阵
代表性 URL
主要主题体系
内部链接观察
技术基础
外链 / 品牌引用线索
第三方数据与日期
优势
不足
不可复制资源
可行动机会
```

## 20. 更新频率

竞争网站不需要每天监控。

建议：

- 新项目立项：完整研究一次
- 重大网站改版：重新研究
- 核心产品战略变化：重新研究
- 重要搜索结果格局变化：重点复查
- 常规维护：每 3—6 个月抽样复查关键页面即可

真正需要长期跟踪的是：

> **结构变化、产品变化、重要内容变化和明显搜索竞争变化。**

而不是每天记录竞争对手某个标题是否改了一个词。
---

## 21. 研究结果怎样进入我们自己的网站

竞争网站研究的最终产物不应该停在报告中。新站、改版或重要产品体系项目应继续进入 [网站架构与内容体系设计](../03-architecture/site-architecture.md)：

- 把竞争网站的页面类型作为外部参照，而不是直接复制菜单。
- 结合自己的关键词页面映射决定真正需要哪些页面。
- 结合真实产品目录决定产品层级。
- 把值得补齐的内容、工具、技术资料和案例放入自己的内容体系。
- 对竞争网站依赖品牌、渠道、用户规模才能成立的结构明确标记为“不直接复制”。

这样竞争研究才能从“观察别人”转化为“设计自己”。
